# The stack profile

The `/work-on` agents are written stack-agnostic. What turns them into specialists is one generated
file, **`.claude/team/stack.md`**, plus its machine-readable twin **`.claude/team/checks.env`**.
`/setup` writes `checks.env` when it wires the git hooks and both files in Phase 7, once the stack is
chosen *and verified*; every agent reads only the
sections for its own role.

Neither file exists in a fresh clone. Until they do, every agent works as a generalist, says so in its
output, and never guesses a command.

## Why a profile instead of editing the agents

- **The agent files stay stable.** A user who edits `implementer.md` never has that edit regenerated
  away when the stack changes.
- **One project can need several specialists.** A web front end and a Go API are two lanes, each with
  its own expert. A persona baked into one agent file cannot be both.
- **It is cheap.** An agent reads one ~80-line file, and only its own section of it.

## Where the facts come from

A persona is only as good as its evidence. Every line is derived — never remembered.

| Fact | Source, in order of authority |
|---|---|
| Language, framework, library | Lockfile and manifest in `app/` → `SPECS.md` stack table → ADRs |
| Versions | The lockfile. **Never** written from memory; leave it out if the lockfile does not pin it |
| Commands | The scripts `/setup` wired up and Phase 5 actually ran green |
| Lanes | The module boundaries `/setup` Phase 3 stated, as real paths under `app/` |
| Idioms | What the repo already does: config files, the first real modules, the linter rules |
| Pitfalls | Version-specific traps of the pinned versions — verify with the official docs or changelog if unsure |
| Caution areas | Migrations, auth, secrets, payments, the deploy config, generated code |

A pitfall you cannot source is not written. An empty section with `— none recorded yet` is honest; a
plausible-sounding one is a lie the implementer will act on.

## `.claude/team/stack.md` — the format

Keep it under ~100 lines. This is plain Markdown under `.claude/`, not a vault note.

```markdown
# Stack profile

Generated by /setup on <date> from <SPECS.md stack table, ADR-000N, app/<lockfile>>.
Regenerated whenever the stack changes. Hand edits: say so in this line, and /setup preserves them.

## Stack

| Layer | Technology | Version | Source |
|---|---|---|---|
| Language | ... | from lockfile | app/<lockfile> |

## Commands

All run from `app/`. Empty means not wired up.

| Purpose | Command |
|---|---|
| install | |
| dev | |
| lint | |
| format | |
| typecheck | |
| test (all) | |
| test (focused) | e.g. `<runner> <path-or-pattern>` — the one agents use |
| build | |

## Lanes

| Lane | Paths | Specialist | Focused check |
|---|---|---|---|
| web | `app/src/web/**` | <framework> front-end engineer | `<focused test for this lane>` |

## Personas

### task-router
One line: what in this stack makes a change *risky* (a schema change, a shared type, a public API).

### repo-scout
Where this stack keeps things: entry points, route tables, schema, test files, generated code.

### work-planner
<Stack> architect. The seams that make two slices genuinely independent here, and the shared files
(barrels, route tables, schema, lockfile) that make them *not*.

### implementer — <lane>
- **You are:** a senior <technology, version> engineer.
- **Idioms this repo uses:** ...
- **Pitfalls at this version:** ...
- **Never:** ...

### reviewer — <lane>
- **You are:** a staff <technology> reviewer.
- **Check first:** the failure modes an expert in this stack looks for (e.g. unhandled promise,
  N+1 query, missing migration down-step, unescaped output).

## Caution

| Path or area | Why | Rule |
|---|---|---|
| `app/<migrations>` | Irreversible against real data | Plan + reviewer, never QUICK_FIX |

Never run automatically: <deploy, migrate against a remote, publish, anything that costs money>.
```

## `.claude/team/checks.env` — what hooks read

Shell-sourceable, so the `pre-push` hook can run the real checks without knowing the stack.

```sh
# Generated by /setup. Each command runs from app/. Empty means skipped.
LINT=""
TYPECHECK=""
TEST=""
# Optional. Makes the test runner leave its machine-readable report (JUnit or
# JSON) where /setup reads it. Never writes board.db - hooks do not.
TRAIL=""
```

Values are the same commands as the `## Commands` table — one source, two formats. If they ever
disagree, the table is the one Phase 5 verified; regenerate this file from it.

## Personas are earned, then refreshed

- **Write it on the first green `/setup`**, never before — a persona for an unverified stack is a
  guess wearing a badge.
- **Refresh it** whenever `/setup` changes the stack, adds a lane, or a major version moves.
- **`/maintain` checks it for drift** — versions in the profile against the lockfile, commands that
  no longer run, lanes whose paths no longer exist.
